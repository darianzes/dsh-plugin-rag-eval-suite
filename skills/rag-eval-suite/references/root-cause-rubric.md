# P0-P3 根因分级与链路归因标准

## 严重度分级定义

| 等级 | 名称 | 触发标准示例 | 上线建议 |
| :---: | :--- | :--- | :--- |
| **P0** | 阻断级 (Critical) | 盲区编造率 ≥ 20%、总幻觉率 > 20%、对抗诱导批量失守、Hit@K < 55%、接口错误率 > 10% | **禁止全量上线**，必须先止血修复并回归通过 |
| **P1** | 严重级 (High) | Hit@K 低于目标阈值、重排截断丢失黄金证据、多跳 Recall 不完整、答案准确率低于目标 | **核心短板**，安排当前迭代优先整改 |
| **P2** | 中等级 (Medium) | 局部数值抽取偏差、误拒率 > 8%、引用溯源不准、尾延迟 P95 超标 | **专项优化**，按模块排期改进 |
| **P3** | 优化级 (Low) | 可观测性不足（未暴露召回列表）、轻量排序/格式打磨项 | **持续治理**，补齐监控与工程底座 |

## 6 层归因解耦原则
1. **先判可观测性**：未观测到召回片段时，不得凭空归因为“检索差”。
2. **先分初排与重排**：若初排命中而重排丢弃，归因于 `RC-RANK-02`（重排截断），而非 Embedding 失效。
3. **再分检索与生成**：若黄金证据已送入上下文但答错/编造，归因于生成层（Prompt/抽取/幻觉约束）；若上游未召回，则不冤枉 LLM。
