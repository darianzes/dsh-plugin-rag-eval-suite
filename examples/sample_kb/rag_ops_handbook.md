# 企业知识库 RAG 检索与上线运维手册

## 知识入库与切片标准流程

知识库离线构建流水线负责将文档解析、清洗、切片并写入混合检索引擎，确保线上检索既兼顾语义相关性又保留专有名词精确匹配能力。

- 常规 Markdown 与纯文本文档采用语义标题优先切片，目标单块大小为 512 tokens，相邻块重叠（chunk_overlap）为 64 tokens。
- 包含表格的文档必须保留完整表头上下文（Header Injection），禁止在表格行中间硬截断，单表超过 1024 tokens 时按行分片并在每片首行重复表头。
- 每份文档入库时必须写入 `doc_id`、`effective_date`、`version` 与 `visibility_scope` 四个标准元数据字段，缺失 `effective_date` 的制度类文档将被准入校验拦截。

## 检索重排与告警阈值

线上采用 `BM25 + Dense Vector` 双路召回，通过倒数排名融合（RRF）合并 Top-20 候选片段，再经 Cross-Encoder 重排截断 Top-5 送入生成模型。

| 监控指标 | 正常绿线 | 预警黄线 | 阻断红线 | 处理动作 |
| :--- | :--- | :--- | :--- | :--- |
| 检索命中率 Hit@5 | >= 85% | 75% - 85% | < 75% | 检查索引新鲜度与分词词典 |
| 端到端 P95 延迟 | <= 2500 ms | 2500 - 4000 ms | > 4000 ms | 触发上下文预算压缩与缓存降级 |
| 幻觉率 (Hallucination) | <= 5% | 5% - 10% | > 10% | 回滚 Prompt 或提高拒答相似度阈值 |

## 故障应急回滚清单

- 确认告警来源属于索引数据异常、重排服务超时还是模型生成漂移，严禁未定位根因前盲目重启向量集群。
- 若发现旧版本文档污染当前问答，立即调用索引清理任务下线已废止版本（如 v1.8）并校验 `effective_date` 过滤规则。
- 回滚完成后必须执行核心集回测（Core Regression），确认命中率、准确率和幻觉率均回到绿线后方可解除告警。
